# PLAN B9.3 — 行结构保持:记录型页面的翻译单元按源行切分(2 会话)

前置:batch-b9.2r。F1 缺陷 #5/#7 的兑现批次。规格输入 = b9.2.2 d 项五病灶(Courier-en p1):①题+导线+页码合成一行;②导线不再右对齐;③页码后署名接同行回绕出孤字行;④行内拉丁名词中断行;⑤色条与条目分段。共同成因:源版面每条目录条目是一条记录(题|导线|页码|署名,行即记录),ParagraphFinder 并成流式段后结构消失。

## 语义

新 policy 键 `preserve_line_structure`(布尔,缺省 false;toc/masthead 声明 true——policy 声明,代码零页型名)。声明页上:

1. **切分**:PageClassifier 判定后、翻译前,magazine pass 将该页段落按**源行边界**拆分为独立段(行 = 源 IL 的行级结构;跨行合并禁止)。样式异质行内(题字体 vs 署名字体)以行为准不再细分——行是记录,记录内混排交给翻译。
2. **每行独立翻译单元**:行文本单独成段送翻(短行受 min_text_length 约束照旧,如实记录未译行——不为此改上游阈值,zh 线同款局限)。
3. **几何**:每行译文回填原行 box,行级排版沿用既有机制(缩放/截断按既有规则);导线(dot leaders)与页码的行内定位如实保持(源行内的 tab/leader 结构若在 IL 有承载则保持,无承载则记录局限)。
4. **守恒**:页级行数不变;非声明页零改动;切分映射入 sidecar(原段 → 行段列表)。

开关 `magazine_line_structure`(默认 False,零差异)。与链/文章归组的作用序:切分在 PageClassifier 后、ChainBuilder 前——toc/masthead 页 chain_eligible 本为 false,链不受扰(断言之)。

## 任务

T9.3.1(会话一):前提复核(a. 源行结构在 IL 的承载——PdfLine 或等价物的可得性与行序;b. ParagraphFinder 合并发生的层位,切分 pass 的插入窗口;c. 导线/页码在行内的表示;d. min_text_length 的作用点与短行的实际命运;不符即停)→ 实现切分 pass + configs(`line_split.json`:声明键消费、行最小字符、sidecar 格式)→ 合成用例门禁(记录行拆分/混排行不细分/非声明页零动/行数守恒/链零扰)→ 默认关零差异 → run_all 全绿 → tag batch-b9.3.1。

T9.3.2(会话二):真实验收——Courier-en 与 FD-en-v2(两份 TOC 形态最重的样张)三臂(OFF/control/ON,b9.2.2 归因地板协议):五病灶逐条前后光栅对照;Vogue p3 顺带验收(#7 的 TOC 半);行级未译清单(短行)如实呈报;两臂译文差异仅限声明页(灵魂断言:非声明页逐字节相同);冻结验收夹具入库;tag batch-b9.3。

## 负向
