# 断言合同变更登记

门禁断言是合同:它写下一个命题,此后每次运行都在证明那个命题仍然成立。命题本身
被后续批次改掉时,处置只有三种——**收窄**(断更弱但仍为真的命题)、**扩写**(断更
强的命题)、**重指**(原命题已被推翻,改断推翻之后仍然为真的那个)。三者都不是删
除,删除会让"这条检查一直在跑"变成"这条检查一直在跑一句空话"。

本登记是这些变更的常驻处。它们此前记在 `WAIVERS.md`,那是不对的:豁免是"偏离约
定、附失效条件"的登记,而断言合同的变更是**永久性内容**,没有失效条件可写,放在
一份按失效条件组织的表里只会永远失效不掉。F3 收口时迁出,原编号保留——`b10.3`
的门禁注释与批次报告按 `W-B10-05` 的写法互相引用,改号会把这些引用打断。

每条记:**原命题 / 为什么它不再为真 / 现命题 / 净强度方向**。

---

## AC-01(原 W-B10-05)`spec_check_b9_2.py` 断言 04a:标题排版配置的范围声明

- **原命题**:`title_typeset.json` 的每个键,跳过 description、`on_floor` 与
  `_allowed_range` 之后,都必须声明自己的取值范围。
- **为什么不再为真**:b10.1 的 T2 引入两张 by_target 表,它们是**对象**,既非数字
  亦非词表,会落进"未声明范围"分支而误报。
- **现命题**:跳过列表改读 `title_typeset._STRUCTURAL_KEYS`(声明在模块里,日后新
  增结构键自动纳入);另加两条——`on_floor_by_target` 的每个值须在平键的词表内,
  `title_min_scale_by_target` 的每个值须在平键的 `_allowed_range` 内。同批次内断
  言 04b 另加两条拒绝用例(越界的按语言下限、词表外的按语言策略)。
- **净强度**:**扩写**。原先只有平键被绑住,现在两张表的每个值也被绑住。
- **批次**:B10.1。

## AC-02(原 W-B10-06)`spec_check_b9_5.py` 断言 01e 与 04f:碰撞动作

- **原命题**:`resolve_collision` **恒不写入**(01e 断该动作没有参数——有参数即
  "声明了它用不上的东西";04f 断一次点名碰撞的决策写不出任何东西)。B9.5 的理由
  是重叠成因异质、对策相反。
- **为什么不再为真**:b10.2 的 T2 定向推翻该决定,并给出机制与一个实施案例
  (AramcoWorld-en-v2 `p3#0`/`p3#4`,y 向 1.3875pt,coverage 0.5234 → 0.35,
  finding 消失而非仅减小)。B9.5 的推理未被推翻,被推翻的是它所立的两个条件。
- **现命题**:01e 改断该动作的 coverage 下限不低于检测器的同名下限——即这个检查
  一直声称在断的东西("动作严于检测器")。04f 的夹具是两块等大文本叠在一处,而这
  正是新规则**仍然拒绝**的类(面积不对称条件在两个等大的段里找不到"较小的那
  个"),故其实质断言(零应用、文档逐字节不变、拒绝理由进升级记录、停机原因不
  变)全部原样保留,只有理由常量从 `REASON_REPORT_ONLY` 改为 `REASON_AREA`,检查
  名随之从 `..._writes_nothing` 改为 `..._refuses_a_pair_of_equals`。
- **净强度**:**重指**。b9.5 门禁不再能证明"该动作不写入"——那个命题已经过期;它
  现在证明的是"该动作不动等大的一对",这是推翻之后仍然为真的命题。
- **后续条件**:若 `resolve_max_area_ratio` 被改动到 04f 的夹具不再落在拒绝侧,该
  夹具须随之重选,或该断言迁往拥有该条件的批次门禁。
- **批次**:B10.2。

## AC-03(原 W-B10-12)`spec_check_b10_3.py` 断言 01f:碎片缝合配置的结构键

- **原命题**:`configs/fragment_stitch.json` 的每个非词表键必须携带
  `_allowed_range`。
- **为什么不再为真**:b10.4 的 T3b 加入 `declared_page_switch`,它是一个运行属性名
  而非旋钮,没有取值范围可言。
- **现命题**:按 AC-01 的既有写法,跳过列表改读
  `fragment_stitch._STRUCTURAL_KEYS`,并追加一条——每个结构键的取值必须是合法标识
  符,即"确实是一个属性名"。
- **净强度**:**扩写**。原先该键根本不被检查,现在它的取值形状被绑住。
- **批次**:B10.4。

## AC-04(原 W-B10-13)`spec_check_b10_5.py` 断言 03f:栏级 reflow 的负向对照

- **原命题**(PLAN_B10_5_REV2 门禁第 2 条):CERNCourier-en p1 零位移,sidecar 记
  "excess 低于阈"而非施加。
- **为什么不再为真**:实测 p1 不是零位移页——其 editorial 版式的主栏 Σ|excess| 为
  47.5pt,两段共上移 18.0pt。计划为 CERN 所引的那组欠填数(10.4 / 54.0 / 71% /
  372.6,标为 p4)也只有最大值 54.0 能在 p4 复现,中位数与占比不能;该组数与本仓
  任何一页都不逐条对应。
- **现命题**(一般形式):每个未施加的栏必须带一个封闭词表内的理由且位移为零,且
  语料中必须确有"excess 低于阈"的栏(该轮 19 栏)。构造性的零位移面由 Vogue-en、
  FD-en-v2(零 flow 页)与 Courier-zh(目标语言在收窄之外)三样张承担。
- **净强度**:**重指**,且比原命题强——三个构造性零位移面强于任何一页的经验零。
- **后续条件**:一次带实测表的计划修订指定一个真正零位移的对照页,或本一般形式被
  写进后续计划。
- **批次**:B10.5。

## AC-05(原 W-B10-14)`spec_check_b10_5.py` 断言 04b/04c:位移的像素证明

- **原命题**(PLAN_B10_5_REV2 门禁第 3 条):位移段 ink 仅现新位置——按字面读,要
  求把位移前的段外框在关臂图上裁下、与位移后的外框在开臂图上裁下,两份裁剪逐字节
  相等。
- **为什么不再为真**:做不到,且不是实现问题。位移是点值而光栅是整格,位移非
  72/dpi 的整数倍时同一字形落在两行之间,被反走样进两行,两张图必然不同(实测 64
  个位移带全部不等)。
- **现命题**,三条可判定断言:(a) 非施加页两臂逐字节相同;(b) 施加页墨量守恒——
  灰度暗于 250 的像素数两臂相差 ≤1%(实测八页逐页精确相等);(c) 两臂在每页画出
  的矢量路径与图像放置完全相同,且每个词的文本与横坐标完全相同,唯一差别是部分文
  本的高度。
- **净强度**:**重指**,且 (c) 比像素比对更强——它排除"重绘成看起来一样",而像素
  比对做不到。
- **先例**:像素逐字节比对对亚像素位移不可用是普遍事实,本条为该类断言的写法先
  例。
- **批次**:B10.5。

## AC-06(F3 开)`spec_check_b7.py` 断言 02a 与 `spec_check_b7_2.py` 断言 05b:空列表的分节

- **原命题**:裁决文件的任何一节写成列表即拒收(`{"terms": []}` 应当被拒)。
- **为什么不再为真**:b10.4 让 `[]` 读作**"这一节我什么也没裁"**,理由写在
  `hitl._require_object` 的 docstring 里:裁决是人照着一份分节为列表的草稿手写的,
  空节自然写成 `[]`,为标点拒收一份文件是拒错了东西。带成员的列表**仍然拒收**——
  它的条目该当何解,没有任何地方定过。
- **现命题**:三个探针改带成员(`[{"a": "b"}]` / `[1]` / `["p"]`),仍断"非对象即
  拒";另**追加**一条正向:每一节写成 `[]` 时被读作空节且什么也没裁定。
- **净强度**:**扩写**。原先只断了一侧,现在这条边界的两侧各有一条断言,且"空列表
  合法"这件事第一次被钉住。
- **批次**:F3(成因在 B10.4)。

## AC-07(F3 开)`spec_check_b7.py` 断言 03a:导出的术语行报的是"观测"而非"定案"

- **原命题**:`hitl.export_terms` 的每行恰有四个字段
  `{source, auto_target, vote_count, first_page}`,其中 `auto_target` 是该词条的定
  案呈现。
- **为什么不再为真**:b10.4 把这两件事拆开。导出报的是**抽取器观测到的**呈现
  (`observed_target`);一行**落成什么**由声明的人名策略在上一层导出
  (`name_harvest.derive`),并在那里被断言(`spec_check_b10_4.py` 的 03e 逐行重新
  推导并比对)。
- **现命题**:行字段改为 `{source, observed_target, vote_count, first_page}`,值断
  言随之改指观测值 —— 即这一层真正拥有的那一半。
- **净强度**:**重指**。定案的断言没有消失,它搬到了定案发生的那一层,并且在那里
  更强(逐行重新推导,而不是比对一个常量)。
- **批次**:F3(成因在 B10.4)。

## AC-08(F3 开)`spec_check_b7.py` 断言 09a:裁决与草稿的关系

- **原命题**:committed 裁决的**每一条**都必须与草稿的机器建议不同——一条与草稿一
  致的裁决即为"机器把自己的草稿当裁决用"的证据。
- **为什么不再为真**:b10.4 之后,草稿对**人名形状**行的建议是**按声明的人名策略推
  导**出来的,而人也按同一条策略裁决。此时"一致"是策略在起作用,不是机器在自我采
  纳。实测:Courier-en 的裁决 14 条术语中 **6 条一致、8 条不同**,页型那一条不同。
- **现命题**:断"**不是整体复述**"——一份裁决只要在它携带的条目上**至少有一处**与
  草稿不同,就是人写的;**每一条都一致**才是那个失败(一个采纳自己草稿的机器会处处
  一致)。
- **净强度**:**收窄**,逐条判据降为整体判据。原命题所保护的失败模式**原样保
  留**;被放弃的是"一致即可疑"这一推论,而该推论在 b10.4 之后本就不成立。
- **代价**:一份只改动一条、其余照抄的裁决不再被这条断言抓住。抓它的是别处:
  `spec_check_b7_5.py` 的真值摘要钉住裁决文件的每一次变化,变更须随会话登记。
- **批次**:F3(成因在 B10.4)。
