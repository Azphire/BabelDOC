# D4 失败分类账(F3 立册)

**静默失败通道**的逐条清点。判据只有一条:**流水线自己的计数器全部说这一页干净,
而读者看到的是坏的**。一个报了错、写了 finding、进了升级清单的缺陷不进本册——它有
人看见;本册收的是**没有任何计数器会动**的那一类。

本册与另外三份配套:`docs/eval/evidence_ledger.md`(数字与出处)、
`docs/eval/gap_register.md`(缺口与不补时的措辞)、`docs/eval/metric_contract.md`
(指标定义)。缺口登记回答"这个缺陷补不补、不补怎么写";本册回答**"这一类缺陷凭
什么会被发现"**——因此每条必须写下**发现它的通道**,那是唯一可迁移的东西。

## 编号与排序

按**首次被记录的批次**排序,同批按报告出现序。编号即注册序,一经分配不改:第八条
是解析层,那个序号在 PLAN_B10_4_REV2 里已被引用为"静默失败第八通道"。

## 状态词表

<!-- state-vocabulary: `已闸` `已收敛` `开放` `构造性` -->

| 状态 | 含义 |
| --- | --- |
| `已闸` | 该通道上已装设显式失败或告警,同样的事再发生会被看见 |
| `已收敛` | 具体病灶已修,通道本身仍无守卫,同类新病灶仍会静默 |
| `开放` | 既无守卫也无修复,按缺口登记的措辞写进论文 |
| `构造性` | 缺陷在本项目作用面之外(上游或源文件),本项目只能观测与登记 |

## FL-01 长链截断转为静默回退

- **形状**:合并后的链长过 `max_tokens`,回复截断、解析失败,按
  `translation_unavailable` 逃生。行为正确——**但它把一条长链变成了一次静默回退而
  不是一次告警**。
- **出处**:`examples/output/b5_smoke/smoke.report.md` §"5. `max_tokens=2048` is
  not chain-aware"。
- **发现通道**:读逐段产物时发现某链的成品是逐段译文而非合并译文。
- **状态**:`已闸`。逃生路径进升级记录,`escalation_surfacing` 的合成覆盖按
  GAP-04 声明收口。
- **相关**:FL-10 是同一形状在另一个请求点上的复发,那一次没有逃生路径。

## FL-02 `translate` 吞掉失败并返回无 PDF 的结果

- **形状**:`translate` 吞掉部分失败并返回一个不含 PDF 的结果;门禁的产物缓存把它
  当作"已完成"发布,此后每个从该 slot 取数的门禁都在一个空工作目录上测出"零一致
  率",并且不报错。
- **出处**:`examples/output/b7_5/refresh.report.md`,T7.5.2.0 维护条目。
- **发现通道**:一致率突然为零而无任何断言转红——数字本身成了通道。
- **状态**:`已闸`。`spec_checks/artifacts.py` 拒绝发布无 PDF 或无 checkpoint 的
  slot,改抛 `BuildIncomplete`;`check_04c_incomplete_build_is_not_published` 复现该
  失败并断言拒绝、slot 不存在、staging 目录留作查看。

## FL-03 人所见与机所匹配的错位

- **形状**:评审单展示给人的文本与翻译器实收的文本不是同一串(占位符与源行边界把
  它们拆开)。**照评审单写出的裁决可以完全无匹配地落空,而且没有任何诊断**——评审
  者看到自己裁决过的词条仍按旧法呈现,而无从知道为什么。
- **出处**:`examples/output/b7_5/refresh.report.md` §"a silent disagreement
  between what a human is shown and what the machine matches on"。
- **发现通道**:把裁决单的输入串与提示词实际文本逐字节对读。
- **状态**:`已闸`。评审单的 terms 节加 `translator_view` 列(人所见与机所匹配并
  排);见 FL-04 的告警。
- **相关**:GAP-21(裁决词条跨源行边界排布时不构成匹配面)是本条尚未闸住的残余,
  仍`开放`。

## FL-04 裁决零匹配即静默落空

- **形状**:一条术语裁决在整篇文档中匹配零次时,流水线照常跑完、照常产出,裁决什么
  也没做,而没有任何东西说出这件事。
- **出处**:`plans/PLAN_B8.md` 需求 2(`p1#9` 裁决静默落空);实现在
  `babeldoc/magazine/hitl.py`。
- **发现通道**:逐条比对裁决与成品文本。
- **状态**:`已闸`。每条 term 裁决把 `matched_prompt_count` 写进
  `hitl_apply.report.json`;为 0 时运行日志显式 WARN。

## FL-05 白名单之外的段不建请求

- **形状**:段落的版面标签不在正文白名单内,或其文本短于 `min_text_length`,则**根
  本不建请求**。没有失败可报,因为没有尝试过。成品里是一段原文,计数器里什么也没
  有。
- **出处**:`examples/output/b8/repair.report.md` §a(`p6#15`,`fallback_line`,
  两次实测);F2 报告 §c"Short lines that never reach a request"(Courier-zh p1 的
  七个栏目名与 p3 的展示标题半句)。
- **发现通道**:检测器 `untranslated_residue`(事后按目标语言字符占比读成品),以及
  读者。
- **状态**:`已收敛`。b10.4 的 T3 给地板加了形状例外(`babeldoc/magazine/short_unit.py`),
  命中声明形状的短段经同一套 prompt 构建器翻译并写回;白名单本身未动,标签在白名单
  外的正文段仍不建请求。

## FL-06 排版兜底吞掉字体异常

- **形状**:标题排版对某段重排时 `typesetting.render_paragraph` 抛
  `KeyError: 'NotoSerif-Bold.ttf'`,被捕获、记日志、段落原样留下。回退是**对的**
  (那一行印得正确),但事实**只写在 `run.log` 里**:sidecar 记该段
  `floor_reached`、`scale 0.583`,不记那次尝试抛过异常。一个不读日志的运行分不出这
  一段与任何其他被降级的标题。
- **出处**:F2 报告 §c"The font failure that is not a silent failure"(FD-en-v2
  `p5#39`);同一失败此前记在 b9.5 收官(Courier-zh)。
- **发现通道**:读 `run.log`。
- **状态**:`开放`。sidecar 未记该事实;跨样张复发已实测两次。

## FL-07 零字符页:没有段落就没有可报的东西

- **形状**:源页不含任何可提取文本(整页一张图),中间语言里该页零字符零段落。**什
  么也没被提供,什么也没被翻译,没有检测器报告任何东西**——因为一个没有段落的页面
  没有可报的东西。本项目的每一个计数器都说这页干净,而读者看到的是整页未译的正文。
- **出处**:F2 报告 §d A3(Vogue-en p2 的 OMEGA 广告;`pymupdf` 对该页返回零字
  符,`create_il` / `layout_generator` / `paragraph_finder` / `typesetting` 四处均为
  零)。
- **发现通道**:读者。目前**只有**读者。
- **状态**:`构造性`。页面无文本层是源文件的事实,本项目不做 OCR;可闸住的是"零段
  落页"这一事实本身应当被记下来而不是被当作干净页。

## FL-08 解析层:碎裂 / 重复层 / 提取序

- **形状**:上游解析把一句话交成几个盒子、把同一串文本交两次、或以与阅读序不同的
  序交出。三者在流水线内部都是合法输入,逐段计数、守恒量、检测器全部正常,坏的是读
  者看到的那一页。**这是第八条通道,也是第一条需要"第二个读法"才能发现的通道**。
- **出处**:`examples/output/b10_4/b10_4.report.md` §5(`babeldoc/magazine/source_audit.py`,
  `tools/source_audit.py`)。
- **发现通道**:**交叉读法**——同一页读两次(流水线的中间语言 + PyMuPDF 词流),
  只用两者不一致的地方。带级按 em 框,碎屑按自身跨度定位,两个方向的不一致分开记。
- **状态**:`已收敛`(A 类真碎裂)/`开放`(通道本身)。全语料实测:A 真碎裂 14
  例,B 重复层 0,丢字 0,提取序故障 0;A 类由声明页缝合处置。source_audit 是本通道
  的**检测器雏形**,尚未进流水线的常规检出面。
- **相关**:GAP-29 立项。

## FL-09 空间重复执行

- **形状**:同一条判据在两处各执行一次。b10.4 的 T3 给长度地板加形状例外,而
  `pre_translate_paragraph` **自己也应用一次地板**,于是例外admit 的每一段回来都是
  `no_text`——例外生效了,地板又把它拿走了,两处各自都"正确"。没有报错,只有一批本
  该被翻译的段落静默地没有译文。
- **出处**:`examples/output/b10_4/b10_4.report.md` §0 第 2 条。
- **发现通道**:跑它,而不是读它。三条修复全部是运行时才现形的。
- **状态**:`已收敛`。`short_unit.prepare` 接管该方法在地板之前的两步(同一构建
  器、同一 tracker 字段),地板不重复。
- **通道教训**:"一个判据只有一个执行点"是可断言的属性,本项目尚未对其他判据做同
  样的清点。

## FL-10 截断静默自默认

- **形状**:一次请求问了 81 个人名的呈现法,回复撞上输出上限、返回截断的 JSON 数
  组、解析为**空**。于是 80 个名字各自默认为自身——而"默认为自身"在成品页面上与
  "策略决定保留原形"**完全无法区分**。
- **出处**:`examples/output/b10_4/b10_4.report.md` §0 第 3 条;
  `configs/name_harvest.json` 的 `render_batch_max` description 逐字记录该成因。
- **发现通道**:读者(名字没变),再回溯到请求。
- **状态**:`已闸`。请求按 `render_batch_max`(25,范围 1..200)分批,门禁断言超过
  该界的表被拆成多次请求且**一个名字也不丢**。
- **相关**:与 FL-01 同形(截断),不同在于 FL-01 有逃生路径而本条没有;解析成空是
  比解析失败更安静的失败。

## FL-11 共享资源别名(跨对象、跨页)

- **形状**:一页之内的几何改写改到了**另一页**。UNESCO Courier 的书眉画在一个
  form(XObject)里,**一张 form 被多页共用**;在 p6 把它抬高 97.9pt,p2 的书眉跟着
  抬高。守恒量按页读时,受害页的段数、文本、逐段配对全部不变——**动的是页面共享的
  那个对象**,不是页面的内容。
- **出处**:`examples/output/b10_5/b10_5.report.md` §2 锚三与 §5 第 1 条(首轮 A/B
  的 `pages_changed` 出现 p2,加锚后消失)。
- **发现通道**:**全文档逐页栅格哈希**。只栅格化目标页的验证看不见它——受害页不是
  目标页。
- **状态**:`已闸`(在 `column_reflow` 内)/`开放`(作为一类)。
  `babeldoc/magazine/column_reflow.py` 的第三条锚拒绝移动画在 XObject 里的段,并把
  该锚作为现成检测器交给后续几何改写 pass;**任何后续几何改写 pass 都要过同一道
  锚**,而这一点目前靠约定而非靠门禁。
- **相关**:GAP-27(跨对象 paint 单例)是同一根源的另一半——那里丢的是图形,这里
  带走的是图形。

## 本册怎么用

1. **新缺陷先问通道**:它是被谁发现的?若答案是"读者",那么无论修不修,都要记下这
   一条——修复关闭的是病灶,通道仍然敞着。
2. **闸的形式只有两种**:显式失败(拒绝继续)或显式告警(写进 sidecar 与日志)。
   "回退并记日志"不算闸——FL-06 就是这么留下来的。
3. **一条通道闸住之后仍留在册里**。册子记的是这一类失败存在过,而不是它今天是否活
   着;删掉已闸条目会让"我们从没有过这种失败"成为可能的读法。
