# B9.1 smoke report

Two samples, both full stack, both reading their direction from the corpus
registry and both carrying the standing person-name instruction. Everything
below is quoted from `evidence.json`, `iteration/round_*.evidence.json` and
`runs.json` in this directory; the paragraph pairs are read from the runs'
`checkpoint.09_il_translated.xml`, keyed by position on the page, not from the
PDFs.

Courier-zh was run once, under the wording of round 0. Courier-en was run once
per wording round, three times in all, because the person-name policy is what
the rounds were tuning and its contents page is where the F1 review faulted it.

Read the three columns against each other before reading any one of them. The
conversion count moves 2, 0, 1 across three wordings, and the two candidates
that account for all of the movement (`p1#20`, `p1#25`) each flip more than
once. This engine is measurably non-deterministic at temperature 0 -- the
project has recorded that since the evaluation protocol was written, and it is
why a significance claim here needs a three-run design. A difference of one or
two candidates between wordings is not distinguishable from the engine's own
run-to-run variance on a single run each, so the honest reading is that all
three wordings convert somewhere between none and a third of the candidates,
and that the iteration did not find a wording that changes that.

The regression at `p1#16` survives all three wordings, including round 2, whose
whole second sentence exists to forbid it. Two names the source gives in
Chinese come back as pinyin. That one is not variance: it reproduced three
times out of three.

Round 1 also disturbed the presentation of ruled names without losing them --
it appended `(Lagipoiva Cherelle Jackson)` and the like after renderings the
ruling had fixed. Round 2 removed that. The ruled renderings themselves
survived every round; see below.

## Historical gates this batch had to correct

The full sweep failed on four assertions the first time it was run after this
batch's changes. None was loosened; each is recorded here with what it was
stating and what it now states.

**`spec_check_b2` :: 10 the magazine package contains no network or LLM
client.** The check searched each module's raw text for the substrings
`openai`, `requests` and `httpx`. `translation_style.py` describes, in its
docstring, the requests a translation run makes, and was reported as a network
client. A substring search cannot tell an import from prose, and the same
tripwire would fire on any sidecar that counts its requests under that key --
`article_context.py` already holds exactly such a key and was only spared by
being on the exemption list. The scan now reads the module's syntax: an import,
static or dynamic, of one of those libraries. It still reports the one magazine
module that holds a client, still reports `babeldoc/translator/translator.py`
when pointed at it, and still reports a module that reaches a library through
`importlib.import_module`.

**`spec_check_b7_5` :: check_05a_truth_files_are_unchanged.** The corpus
owner's files are pinned at their delivered digests. The registry moved because
the owner added the two direction fields, which is the revision this batch is
built on. That assertion's own comment says a revision arrives with a session
that says so and repins these, so it was repinned. What the pin no longer
covers is covered better elsewhere: `spec_check_b9_1`'s 04a2 compares the
registry against the previous commit field by field and fails if anything other
than those two fields moved.

**`spec_check_e0` :: check_07b_the_runner_registers_this_gate.** E0 requires
every `b` gate to run before it, since it cites what those batches left. The
new gate had been appended to the end of the runner's list, after the
evaluation gates. It was moved to sit after `spec_check_b8_4.py`, which is
where a batch gate belongs.

**`spec_check_e2` :: check_06_no_upstream_and_no_ground_truth_change.** E2's
scope assertion reads the union of its session tags, and falls back to the
working tree while one of them is uncut. It named `batch-e2.1`, a tag that was
never cut and never will be: that session's work rode into the `batch-e2.2`
commit, which CLAUDE.md records. The uncut branch was therefore permanently
open, so from the moment any later batch began editing, E2 read that batch's
working tree as its own delta -- this batch's files were reported as E2 scope
violations. The tag list now names the two tags E2 actually cut, which is where
its whole delta is. This one was a latent defect that would have fired for
every future batch, not a consequence of anything B9.1 did.
