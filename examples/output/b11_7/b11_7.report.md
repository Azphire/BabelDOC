## 2. T2 —— 链回填按类分策(用户裁决)

body 链改**容量切**:切点为盒一自身容量,经目标语言 break_rule 合法化,再自行首
禁排标点向前回吸。栏界与页界**同等对待** —— 被栏边打断的正文段与被页边打断的
是同一个段被打断,一个应答边界种类而非文本的切法回答的是另一个问题。

### 2a. 试装实现方式的判定(计划点名要求)

**排版器自身的 packer 不能用**,三条理由记在 `t2_cut_prediction.json` 的
`implementation.why_not`:

1. `_layout_typesetting_units` 是 stage 的方法,要它的 font mapper,而后者由运行
   配置在 stage 处构造,更早不存在;
2. 它吃的是 `create_typesetting_units` 从**已排字符**造出的 TypesettingUnit,而
   链被切的那一刻译文只是字符串、背后没有字符 —— 没有东西可供它装;
3. `chain_backfill` 自述为纯模块,导入 stage 会把 font mapper 拽进翻译阶段。

故取**行栅算术**,两个数由 b11.6 冻结运行**实测**而非猜定:CJK 目标 advance
1.00 / line_skip 1.50,Latin 目标 advance 0.473(p10–p90 = 0.464–0.492)/
line_skip 1.30。后两个 line_skip 与 stage 自身硬编码的值逐位相同,是这份测量的
自校验。

### 2b. 两法对照(同一合并源、同一联合译文,只变切法)

在 b11.6 冻结的 18 条可测 body 链上各切一遍:

| 量 | 句界切 | 容量切 |
| --- | --- | --- |
| 盒一溢出 | **11 / 18** | **3 / 18** |
| 逐链质量(不溢出优先,其次末行填充率) | — | **15 优 · 0 劣 · 3 平** |

**质量为什么是二元组而不是填充率一个数**:切过盒容量会使盒溢出,stage 随即整段
缩排,而单看填充率会把那次溢出记成"末行满" —— 一次使页面变坏的切法会因此冒充
一次改善。故先比是否溢出,再在装得下的里比末行。

**行首禁排标点的类从何来。**计划要求"复用排版器既有标点分类"。b5 的 08e 又要求
两个链模块**只能**从 `babeldoc.magazine` 导入 —— 那正是该模块自述的纯度。两者
的解法:该词表声明在模块本就读的配置里,门禁 `02h` 把它钉成与 stage 常量**逐字
节相等**。相等比导入强:导入只能说名字来自哪里,相等能说两份内容一致,任一单独
被改即当场为红。

### 3a. 这个零是真零 —— IL 40 / canvas 0 的成因

`residue_evidence.json` 记 canvas 0 而 IL 40,两数**并不矛盾,也不是丢段**:
`checkpoint.11_typesetting` 在**修复回路之前**落盘,故它是修复前的快照;
canvas 是修复后的终态。四行版权行的英文译文在页面上有几何证据(上表),两条被
车道重排的段(`p5#9`、`p6#15`)其 `unicode` 停留在修复前的中文,而其
**composition 字符**已是英文 —— 写出端画的是后者。

**这一条必须写明**:后人若把这两个数并排读,会把它读成一次内容丢失;而本批确实
发生过一次真的内容丢失(见 §3d),两者形态相近而性质相反。判据是渲染证据,不是
checkpoint。

### 3b. 方向化的两个界

- **检测地板**:`residue_min_script_chars_into_en = 1`,zh 侧维持 12。论证:zh
  目标下拉丁残留有合法存在(品牌、URL、地址),地板有保护对象;en 目标下 CJK
  零合法存在,地板只挡住残留而不挡噪声。
- **修复界的比例**(用户裁决):`min_residue_ratio_into_en = 0.05`,zh 侧维持
  0.9。论证同上。**长度界不降** —— 裁决明确:检测地板管看见、修复界管动手,二者
  非镜像;降界会把一条版权行的三个碎片逐片送译、断名产出计数器看不见的垃圾拉丁
  文本,属指标游戏。病灶是碎裂,改的应是碎裂。

### 3c. 阅读序:一处比计划设想更靠前的病灶

计划称"修复侧以存储序喂引擎、检测侧以阅读序读文本,两侧字符串不一致"。**实测两
侧都拿到倒排串** —— 它们本就共用 `rendered_text`,坏的是那个共用函数:
`reading_order._advance` 只统计**单元内部**的步长,而旋转铅字每个单元恰好只有一
个字符,于是两轴步长皆为零、无轴占优,函数遂返回存储序并称之为阅读序。

修法落在共用函数上,故一次修好两侧。方向不能取自存储序(那样排序必然复现存储
序,是一个恒等变换),而取自**写出端自己的矩阵**:`vertical` 为真的字符由写出端
展开为 `0 1 -1 0`,该矩阵下笔锋沿页面向上走,故阅读序是 y 升序。

作用面实测:四样张共 **17 段**被重排,**全部 `vertical=True`,零横排段被触碰**。
中途一版曾把 5 个横排段打乱(`IMF.org立即访问` → `I立即gMFor.访问`),故加了"所
有字符须站在一列字宽之内"这道几何闸,该闸的比较对象是字符自身实测宽度,不引入
任何阈值。

### 3d. 我引入并修掉的一次内容丢失

改判使段文本变长;盒装不下时 stage 留下**空 composition**,而写出端对空
composition 的应答是**拒绝导出该段** —— 行不是留着未译,而是**从页面上消失**。
p5 页脚曾整行消失。

现有还原闸(`restore_unformatted`):排版不出就把本 pass 替换掉的 composition 与

坏。**§4.18 的消费者清单未预见此项 —— 清单答了"typesetting 会把它当文本断行",

### 3f. 旋转写回车道(T3.4)

三处承载点逐一判定(`t3_lane_feasibility.json`):

| 站点 | 承载 | 车道怎么做 |
| --- | --- | --- |
| 渲染端 | **是** | 一字不改。两条路径都对 `vertical` 字符发 `0 1 -1 0`,锚在盒右下 |
| 字符矩阵 | 否 | 车道**自己**在它摆放过的字符上置标志 |
| packer | 否 | 递给它一个**转置盒**,再把结果旋转回去 |

**计划 T3.4a 要求的上游一行修改,本批没做,而且不该做。**`typesetting.py:861`
构造的是 stage 自己排出来的译文字符;让它继承段落标志,会把**每一个**旋转段的每
一个译文字符都标成竖排 —— 包括车道从未认领、stage 已按水平摆好的那些 —— 渲染端
随即把它们旋转着画在水平位置上,比原缺陷更坏。车道的作用面恰为它认领的段,无需
任何上游改动。这是一次**收窄**,登记在 UPSTREAM_DIFF 的"未做的改动,与为什么"。

另一处措辞更正:计划写"per-char 矩阵**取源旋转**"。IL 只有布尔、没有矩阵,且
schema 冻结;写出端把该布尔展开为**唯一**那个 90° 矩阵。故"源旋转"在现行 schema
下只有一个取值,本语料三处实测方向统一为 (0,−1),布尔充分;方向非此者**不入车
道**,已在可行性记录中登记(诚实界)。

### 3g. 折叠规则:实测推翻了 REV2 的撤销前提

REV2 撤销初版"反向括注"的独立地位,理由是"正确阅读序文本在 translate 档下自然
输出拉丁原名",并留其为**门禁失败备选**、"不实现"。

**关掉折叠实跑:canvas = 8,不是 0。**原因不是模型译错,而是 p3 **根本到不了任何
